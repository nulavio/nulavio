Private by default. Honest by design.

Nulavio is a browser for Linux built on Mozilla's Gecko engine. It comes with tracking protection set to Strict, installs the uBlock Origin blocker on first launch, and sends no data to Nulavio servers: the project runs no service that receives data from the browser.

This page is written like an engineering document. Each claim says what it costs or where it stops, and where to check it: the file, the test or the recorded decision behind it. What is not ready yet is marked as not ready. Numbers, excerpts and captures come from commit {{origin}}.

The code is licensed under the MPL-2.0, but the repository is still private. Until it opens, the paths quoted here are references, not links.

2 Defaults we change

Nulavio changes few engine defaults, and all of them in the direction of sending less.

The privacy defaults live in browser/config/prefs/baseline.js, each with its reason (@why) and its cost (@tradeoff); a test refuses a pref without them. What applies only to the Nulavio build lives in browser/branding/nulavio/pref/firefox-branding.js, with comments. You can change any of them in the engine's settings or in about:config, and your choice stays in the profile.

2.1 Strict tracking protection

Blocks trackers, cross-site cookies, cryptominers and known or suspected fingerprinters, in every window.

Cost: Some embeds and logins may break. The shield in the address bar turns protection off for that site only, and Mozilla's compatibility exceptions stay on.

A bug we had. Until 2026-10-26, the build requested Strict only as a distribution default, and the engine recomputed that value to Standard. Since then Nulavio writes Strict once into each profile, and the test checks the mode in effect and a really blocked tracker, not the requested value.

2.5 No early connections

The browser does not connect to a site before you choose to go there: no pre-connecting while you type, from suggestions, or when the pointer rests on a bookmark. WebRTC only offers the default route's address, so local and VPN interfaces are not exposed.

Cost: The first response of some pages may take slightly longer, and rare direct calls between computers with several networks may need a relay server.

Some engine protections need the network. We keep them, because turning them off would leave you less protected.

So «Nulavio has no server» does not mean «the browser never connects to anything».

3.4 Signed extensions, and uBlock Origin

Extensions load only with Mozilla's signature. uBlock Origin is installed by a build policy: on first launch, the browser downloads the version the project records (today {{ubo}}) from addons.mozilla.org and checks Mozilla's signature. After that it updates like any extension, and its filter lists also update over the network. It works in private windows, and you can disable it or turn it off for one site.

Limit: On this path the engine checks the signature but not the SHA-256 the project records. The SHA-256 is checked when Nulavio installs a password extension (section 9).

4 What you type

In most browsers, what you type in the address bar goes to the search engine while you type. In Nulavio, nothing goes before Enter unless you turn suggestions on.

4.1 Nothing goes to a search engine while you type

The test types into the real address bar, key by key, and records every request the browser makes. Typing and focusing the bar send nothing to any search engine, also with shortcuts like @google or @ddg.

Limit: The test measures HTTP and HTTPS requests, not DNS, so a word that looks like an address may still be looked up in DNS. Early connections and single-word DNS lookups are off to reduce this.

4.4 DNS, chosen once

On the first new tab, Nulavio asks once how to look up sites. There are three options: through your computer's resolver; through encrypted DNS, with your computer's resolver as a fallback; or through encrypted DNS only. The encrypted resolver is one you choose: Cloudflare, Quad9, Mullvad or your own address. Until you answer, the engine's default applies. Nulavio receives nothing either way.

Cost: In encrypted-only mode, if the resolver fails, sites do not open, including networks with a sign-in page, rather than falling back to plain DNS.

Limit: Encrypted DNS changes who sees your lookups; it does not hide the sites you visit.

5 Profiles and routes

Work, banking and personal use can live in different profiles that share no sign-ins or history. Rules of yours decide which profile each link opens in.

5.1 Profiles that do not mix

Each profile is a separate engine instance with its own folder (directories 0700, files 0600). Cookies, site data, history, extensions, passwords saved in the browser and preferences do not cross from one to another. Switching never opens a second copy of a profile that is already open.

Limit: Switching profiles does not bring your sign-in along: in the other profile you sign in again. Profiles separate what the browser keeps, not your internet address or the browser's fingerprint, so a site visited in both can still tell it is the same computer.

5.2 The band: which profile you are in

At the top of every window, above the address bar, a band drawn by the browser shows the profile, with a colour, an icon (or the name's initial) and a name, and its state in words and with a symbol, never by colour alone. Web pages cannot write in this band; only Nulavio's own pages are named in it. When Nulavio cannot read the state, the band says «Protection unknown» instead of guessing. In full screen it becomes a thin line at the top.

«No password» means that profile's files are not encrypted on disk. The protections in section 2 apply to every profile.

6 Protected profiles

A protected profile stays encrypted on disk while it is locked. Once open, it works like any other.

6.1 Encrypted while locked

The profile's files live in a gocryptfs volume, with XChaCha20-Poly1305 and the file names encrypted too. While locked, the profile is an empty, read-only folder, and a copy of its files does not open without one of the unlock methods. It locks again when its last window closes. You create a protected profile from the browser itself, in three decisions.

Cost: Protected profiles need gocryptfs and FUSE installed on the system; without them, the creation page says what is missing.

6.2 Ways to unlock, with no master key

Each protected profile has its own key, 32 random bytes, which is only ever stored inside encrypted envelopes, one per unlock method. Today there are three methods: the profile's password (Argon2id), a 140-bit recovery code and your computer login, through the system keyring. The code is shown once, in 7 groups of 4 characters, and the only copy the page offers is printing it. There is no Nulavio master key: if you lose every method, the data cannot be recovered, and profile creation tells you so.

7 Guard: what changed while the browser was closed

If another program changes your profile while the browser is closed, Nulavio shows the change the next time it opens.

Every time it starts, Nulavio Guard compares the profile with its record of the last run: extensions, protection and network settings, certificate authorities, security modules, native-messaging programs, policies, user.js and search engines. Each change made outside the browser appears on a page, with Undo where possible, or Keep. Extensions, settings and search engines you change inside the browser do not appear. A certificate authority or security module you add in the certificate manager appears at the next start, for you to keep. Temporary profiles and profiles an agent is driving are not checked. In a protected profile, Guard's record stays encrypted while the profile is locked.

Limit: Guard detects; it does not prevent. A change to user.js has no Undo on the page: you fix the file by hand or keep it. A program running as you while the profile is open can also rewrite Guard's record and hide what it did. Guard catches common tools and forgotten changes, not malware built to fool it.

8 AI, only when you ask

Mozilla's AI features are off (2.6). Nulavio has two paths of its own; both stay idle until you set them up, and both follow the same permission policy.

8.1 Assistant

You choose the provider: any service compatible with OpenAI's chat API, including a model running on your computer, or Anthropic's API. Its address must be HTTPS or on this computer. Nulavio runs no model and no proxy, and has no account. The key stays in the system keyring and never enters the browser. Only profiles you allow can ask. A page's text goes only when you click «Include this page», and only that tab's text; if you switch tabs, it leaves the message, and the panel tells you.

Before Send, a line says where the message goes (address and port), which model answers and the total size, Nulavio's instructions included. If the recipient or the size changes before sending, the send is refused and nothing leaves. While an assistant task acts, the window's band says so and offers «Stop task».

In private windows the assistant does not work.

Limit: The provider you choose sees what is sent to it, and a model misled by a page can still act within the assistant's permissions.

8.2 External agents

Agents like Claude Code and Codex CLI use the browser through a Nulavio MCP server, which they start themselves and talk to over standard input and output. Each agent works in an AI Workspace, a profile of its own. It enters one of your profiles only if you give it that profile, and never a locked one. Every call goes through a decision outside the model, in this order: emergency stop, revocation, site list, explicit grant, level. Page text cannot change permissions. The log keeps actions, not content.

9 Passwords, in your manager

Nulavio has no password vault of its own and does not read yours.

It works with the official Proton Pass, KeePassXC and Bitwarden extensions. When you choose one in Settings → Passwords and confirm, Nulavio installs the pinned version of the official extension, checking the recorded SHA-256 and Mozilla's signature, and turns off the browser's own password prompts. Switching back to the browser's manager does not remove the extension or delete saved logins.

Proton Pass (Partly)
Sign-in and autofill with a real account worked on 2026-10-25 in Nulavio Preview, the test version that runs on your distribution's Firefox. On the Nulavio build, the official extension loads and the chooser installs the pinned version; the real sign-in still has to be repeated.
KeePassXC (Partly)
Pairing and autofill end to end with KeePassXC 2.8.0 and the distribution's Firefox, in a Fedora 44 container, in CI (pushes to main and pull requests). Not yet tested on a real desktop.
Bitwarden (Partly)
It installs, its signature checks out, its background process starts and its window opens. Sign-in with a real account has not been tested.

9.1 Look-alike address

When you open a site whose address imitates one where you have a login saved in the browser, Nulavio warns you before you type the password. The real site is never warned about.

Limit: The warning only compares with logins kept by the browser's own manager. With Proton Pass, KeePassXC or Bitwarden, Nulavio does not read the vault, so it has nothing to compare with.

10 What a browser cannot fix

Some threats are out of any browser's reach. We would rather write that down before anyone asks.

  • A malicious program running as your user can read the open profile (cookies, sessions, history), install extensions and change settings. The 0700 and 0600 permissions protect against other accounts, not against yours.
  • A program with root access sees everything.
  • Anyone with physical access to an open session also sees everything.
  • Anonymity against someone watching the whole network is not the goal; that is what Tor Browser is for.
  • Browser fingerprinting is only reduced. In our measurement of 2026-10-26, on Firefox 158.0.1, Strict mode rounded the reported processor count (16 to 8) but did not change the canvas reading on the test page.
