# UX/UI audit, 2026-10-27

Phase 0 of the [UX redesign programme](../product/execution-plan.md#ux-redesign-programme-from-2026-10-27). Build audited: Track B on Firefox 158.0.1, `main` at 40149a2 (Shell of S11, patch 0007), pt-BR, light and dark. The redesign is implemented on Firefox 159.0, the engine `main` moved to the same day.

The audit combined:
- headless captures of every reachable surface;
- a heuristic review (Nielsen plus the frontend-design rubric);
- a model-state review of the assistant (ai-interface-design);
- a study of the engine source to see what Firefox already ships;
- a reference study: Zen read from its MPL-2.0 source; Dia, Arc, Opera Air and Vivaldi from public sources, ideas only.

It found **107 problems: 6 blockers, 53 major, 42 minor, 6 polish**. Every finding, with its evidence and fix, is in [audit-2026-10-27-findings.md](audit-2026-10-27-findings.md). The "before" captures are in [screenshots/2026-10-before](screenshots/2026-10-before/), and the decision that followed is in [visual-directions.md](visual-directions.md).

## What works and stays

- **Tokens and theme.** One token source with a CI freshness check, and every declared contrast pair passes. Horizon is small and gated by a pref. Its layers let the contrast and forced-colours layers win, and it never restyles the address-bar security UI.
- **Honest copy.** Every DNS choice says what it protects against and what it does not. Errors end with "Nada foi alterado". The recovery and phone flows state their limits.
- **Safe behaviour.**
  - Held addresses are shown as text and never loaded.
  - Programs are never opened from the downloads UI (patch 0007).
  - The API key lives only in the system keyring.
  - Page text comes from the engine's extractor and is marked untrusted.
  - Answers are plain text.
  - Deny is focused on agent requests.
- **Locales.** en and pt-BR have identical keys (771/771).

### P1. Security states are not visible enough

- **Current profile.** It is a 16 px colour and initial among the extension icons; it can overflow or be unpinned, and Pessoal and Pesquisa are both "P" (WCS-03).
- **Protected profiles.** A protected profile that is open looks like a plain one, and the locked state is dropped from accessible names (SPA-02, SB-04, WCS-04, SPA-10).
- **Temporary, AI Workspace and Guard.** Each is only a dismissible notification bar. An agent in the user's own profile gets the same words as an isolated AI Workspace (WCS-02, WCS-05, WCS-07, AI-06).
- **Private windows.** The cue is an icon only, with no words, and the tint is lost under installed themes (WCS-06).
- **Spoofable Nulavio pages.** Nulavio's own pages, including the vault password pages, show the generic "Extensão (Nulavio Shell)" chip (SB-06, WCS-08).
- **Agent controls.** Agent activity, pause, revoke and the emergency stop exist only deep in Settings (AI-05).

### P2. Structure and flow

- **Settings** is one 3.7–4.5k px page:
  - its navigation pills wrap and do not show the current section;
  - there is no search;
  - one status line sits far from the controls;
  - its scope claims are wrong;
  - it mixes two save models (SPA-04, SPA-05, SPA-06, SPA-15, SPA-16).
- **New tab.** Mostly slogan, a duplicate search box, generic shortcuts and help text. The protection status falls below the fold, and the page never says which profile you are in (SPA-14).
- **Profile popup.** Templates create a profile in one click and look like existing profiles; there is no running or locked state (SPA-09, SPA-17).
- **Routing pages.** They never name the current profile and dead-end when the target is locked (SPA-07, SPA-08).
- **Assistant.** It is single-shot, with no stop, no streaming and no provenance. Truncation is hidden, and every error collapses into "confira a chave" (AI-03, AI-08, AI-09, AI-13).
- **Vault.**
  - There is no UI to see or change unlock methods, or to replace the recovery code.
  - The recovery-code step has no save or print aid (SB-08, SB-09).

### P3. Design system, accessibility and tests

- **Missing tokens:**
  - type roles in rem;
  - translucency with a solid fallback;
  - elevation that changes per theme;
  - motion easings, z-index, scrim and selection;
  - reserved security cues.
  
  One-theme tokens also slip through the generator (DS-02, DS-04, DS-08, DS-09).
- **Shell CSS:**
  - the start-page sheet doubles as the base sheet;
  - h1 uses six different classes;
  - there are 12 raw font sizes;
  - pill primaries sit next to 10 px secondaries;
  - important headings are 13 px uppercase card titles;
  - `aria-pressed`, `aria-invalid` and loading states are missing;
  - native radios render in Firefox blue (DS-05, DS-07, DS-11, DS-12).
- **Contrast and transparency.** Shell pages ignore prefers-contrast and forced colours. prefers-reduced-transparency is handled nowhere; in moz-extension pages it is not even parsed without a pref that would also expose it to websites (DS-02, DS-06).
- **Tests.**
  - The rendered Track B checks never run in CI, which uses distribution Firefox.
  - `test_07` cannot catch a layout that pushes security indicators off-screen.
  - pngdiff pins no UI (DS-01, DS-03, DS-15).

## What Firefox already ships (reuse before building)

| Feature | State | Reuse in Nulavio |
|---|---|---|
| Vertical tabs, expand-on-hover strip, pinned tile grid | `sidebar.verticalTabs` off; `sidebar.visibility`; animation prefs honour reduced motion | Prefs plus Horizon tokens; layout presets |
| Tab groups (name, colour, collapse, saved) | on | Re-value the nine colour names with tokens, kept apart from identity colours |
| Split view, two panes, per-pane insecure footer | on | Restyle and keep the footer |
| Compact density, auto-compact | on | Already re-valued by Horizon |
| Address-bar quick actions (`>`) | on; `ActionsProviderQuickActions.addAction` usable from a privileged module | Nulavio actions in the address bar, without a patch |
| `-moz-pref("name", "value")` in chrome CSS | on, live | Per-profile identity and states, without a patch |
| about:keyboard | on | Linked from Settings |
| backdrop-filter | on (GPU blocklist; costly on software rendering) | Only inside the window, with an opaque fallback |
| Translucent windows on Linux | absent | Not pursued |
| prefers-reduced-transparency | chrome only; on GTK it mirrors high contrast | Every translucent surface gated, plus a Nulavio setting |
| Mozilla AI (chatbot, smart tab groups, Link Preview key points, Smart Window) | on, or one Nimbus flip away | Off by prefs; the Nulavio assistant is the single governed AI |
| Windowed toolbar autohide | absent (fullscreen only) | Not built: it would hide security UI |

## Comparison with the references

| Reference | What Nulavio lacks | What Nulavio has that they do not | Not adopted |
|---|---|---|---|
| Zen (MPL-2.0; 272 engine patches) | Visible window identity, a layout choice, a focus preset, a restyled vertical list | Real isolation per profile (Zen's spaces share history and extensions); security UI kept visible | Reparenting the toolbox, hiding tracking/permission icons, toolbar autohide, rebinding standard keys, a remote mods store, silent re-routing, a floating content card, gradient and grain |
| Dia | Contextual entry points, tab-bound context, a thread with stop | Bring-your-own provider, no account, per-profile consent, local key | Cloud account, vendor proxy, Memory, auto-classifying typed text as chat |
| Arc (sunset 22 Dec 2026) | One identity token used everywhere, frame identity, command actions | Smart Routing with held addresses, locked profiles | Account, synced user JS (Boosts CVE), auto-archive, gradient themes, swipes |
| Opera Air | Calm surfaces, progressive disclosure | No engagement features | Frosted wallpapers, glass tinted by page colour, camera exercises, health claims |
| Vivaldi | Layout presets, shortcut customisation, a contrast option | Personalisation never touches protections | Page-colour chrome, UI auto-hide, theme gallery, macro engine |
