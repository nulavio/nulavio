# ADR 0007 — Nulavio AI Bridge: MCP for external agents, one policy decision point, an AI Workspace per agent

- **Status:** Accepted (2026-10-26). **Foundation implemented (S4)**: `nulavio ai`, MCP server, AI Workspace, Policy Decision Point, audit; tested with real Claude Code. Real profiles, Shell UI and the built-in assistant come later (S7, S8, A12).
- **Related:** [brief](../product/briefs/2026-10-26-ai-bridge.md), [architecture](../architecture/ai-bridge.md), [threat model for automation](../security/threat-model-ai.md), [compatibility matrix](../ai/compatibility.md), [ADR 0003](0003-nulavio-profiles-and-routing.md) (profiles), [ADR 0006](0006-nulavio-vault.md) (Vault).

## Context

Users want AI agents (Claude Code, Codex, others) to use the browser, with autonomy ranging from "read only" to "full control". The engine already has a standard automation protocol (WebDriver BiDi). An agent that speaks it directly is the most capable option, but it is also all-or-nothing: whoever holds a BiDi connection controls the whole browser, every profile it has open, and can disable protections. Nulavio needs a layer that agents can use without setup friction, that applies the user's choices on every call, and that never trades the user's protections for convenience.

Audit (A0), 2026-10-26:
- Engine: Gecko 158.0.1 (Nulavio build, Track B) and distribution Firefox 158.0.1 (Track A). Both ship the Remote Agent with WebDriver BiDi; CDP was removed from Firefox in 141.
- No automation code existed outside the tests (Marionette client in `tests/lib/marionette.py`). The launcher refuses `--marionette`, `--remote-debugging-port` and similar flags for normal profiles (`engine.FORBIDDEN_FLAGS`).
- The Remote Agent applies "recommended preferences" by default. In 158 these **turn off Safe Browsing (phishing, malware, downloads), app and extension updates and the pop-up blocker**, among others (`remote/shared/RecommendedPreferences.sys.mjs`). They suit test farms, not a browser that visits the real web.
- Clients present: Claude Code 2.1.308, Codex CLI 0.164.0. Neither Claude Desktop nor Codex Desktop is installed.
- MCP: the latest specification is 2026-07-28 (stateless; `server/discover`; per-request `_meta`). Clients in the field still use the 2025 `initialize` handshake.

## Options

| Option | For | Against |
|---|---|---|
| A. Agents speak WebDriver BiDi (or Marionette) directly | Maximum capability; existing tools (Puppeteer, Selenium, firefox-devtools-mcp) | No per-agent policy: a connection controls everything; port open to every local process; recommended prefs weaken protections unless the tool turns them off |
| B. Point agents at Mozilla's firefox-devtools-mcp | Maintained by Mozilla; many tools | Node.js dependency; its own launch and prefs; no Nulavio policy, audit or profile model |
| C. **Nulavio MCP server (stdio) + Policy Decision Point + AI Workspace, driving the engine over BiDi** | One place for grants, audit, revocation and stop; works with any MCP client; no change to the engine | Fewer tools than raw BiDi at first; the bridge must keep up with the protocol |
| D. Engine patch with a built-in agent API | Fine-grained control inside the engine | Large patch surface on every engine update; not needed for the first slices |

## Decision

1. **C now, A as an explicit "raw automation" option later.** The MCP server is the default path. Raw BiDi for advanced users (A13/Full control) will be a separate, explicitly enabled mode that says plainly that the protocol bypasses the bridge's per-call policy.
2. **Transport: MCP over stdio, started by the agent** (`nulavio ai serve`). No network listener for agents; the only listener is the engine's BiDi endpoint on `127.0.0.1` with a random port, which the engine protects against web pages (it rejects WebSocket upgrades that carry an `Origin` header or a foreign `Host`). The server is **dual-era**: it answers `initialize` (2025-03-26, 2025-06-18, 2025-11-25) and modern 2026-07-28 requests with `_meta` and `server/discover`. Standard library only (decision D6): no SDK dependency, tested against real clients.
3. **Agent identity: a token per registered agent**, generated by `nulavio ai add`, shown once, stored only as SHA-256. It identifies the *configuration* that launched the server, not the program; any same-user process that reads the agent's config can present it (documented, threat model AI-T7). Unknown or revoked tokens: the server refuses to start.
4. **Policy Decision Point outside the model** (`ai/registry.decide`). Order: emergency stop → revocation → site list → explicit grant (allow/ask/block; forever, for N minutes, or for one bridge session) → autonomy preset. "Ask" goes to a desktop dialog outside the browser the agent controls (KDE `kdialog`); with no way to ask, it fails closed. No MCP tool reads or changes policy; the policy file is re-read on every call, so changes apply to the next call.
5. **Autonomy levels** (presets per capability; the user can override each capability):

   | Capability | Restricted | Assisted | Autonomous | Full control |
   |---|---|---|---|---|
   | read pages, navigate, screenshots | allow | allow | allow | allow |
   | click and type | ask | allow | allow | allow |
   | submit forms | ask | ask | allow | allow |
   | files, signed-in sessions, background work | block | ask | allow | allow |
   | purchases, account settings | block | ask | ask | allow |
   | local network / internal pages, JavaScript, network inspection, other profiles, private tabs | block | block | ask | allow |
   | cookies and storage, privileged debugging | block | block | block | allow |

   Full control needs an explicit acceptance of a warning (`--accept-full-control`; the Shell screen in S7). "Autonomous" never asks again for what it covers (tested).
6. **AI Workspace: one engine profile per agent**, separate cookies, history, downloads and storage; persistent or disposable. It is the only place where the Remote Agent runs. Its prefs are the Nulavio baseline plus `remote.prefs.recommended=false`, so Safe Browsing, updates and the pop-up blocker stay on (tested with a positive control). Sandboxes are untouched (`engine.launch_env`). `navigator.webdriver` is true there, as the standard requires; sites can tell automation apart.
7. **Addresses are classified before navigation** (`policy.classify_url`): http(s) only by default; the local network, this computer, `file:` and `about:` pages need `local_resources` (and `debugging` for privileged pages); `javascript:`, `data:` and URLs with credentials are refused. Clicks that follow a link or submit a form are checked against those capabilities too.
8. **Audit keeps actions, not content**: agent, session, tool, capabilities checked, decision and reason, target origin, outcome, duration, sizes. Never page text, typed text, scripts or screenshots. Rotates at 2 MB.
9. **Real profiles are not reachable in S4.** Access to Personal/Work/Banking, Smart Profile Routing per agent and locked profiles come in S8 with the Vault rules: automation permission never implies a key; a locked profile stays locked.
10. **Nulavio never edits another program's configuration.** `nulavio ai add` prints the exact MCP configuration for Claude Code (JSON) or Codex (TOML); the user adds it. A one-click setup (S8) will show the exact file and diff and ask first.

## Consequences

- Any MCP client can use the browser with one command and one configuration block; the user's choices apply to every call and can be withdrawn at once (revoke, stop).
- The bridge only governs what goes through it. A CLI agent with shell access runs as the user and can do anything the user can, including editing Nulavio's files or starting its own browser; the bridge does not and cannot prevent that. This is stated in the UI and the threat model.
- Pages can still do what pages do once loaded (redirects, scripts, requests to the local network); the PDP decides what the *agent* asks for. Engine protections (Safe Browsing, ETP Strict, HTTPS-Only, pop-up blocker, sandboxes) remain the defence for page behaviour.
- The tool set is smaller than raw BiDi or firefox-devtools-mcp. It grows per milestone (downloads, uploads, network inspection, profiles), each with its capability.

## Implementation (S4, 2026-10-26)

Package `launcher/nulavio_launcher/ai/`: `mcp.py` (protocol), `tools.py` (11 tools and per-call enforcement), `policy.py` (capabilities, presets, address classification), `registry.py` (agents, grants, stop switch, approvals), `audit.py`, `workspace.py` (engine launch), `bidi.py` and `websocket.py` (protocol client), `cli.py` (`nulavio ai add | agents | grant | autonomy | revoke | remove | stop | resume | audit | capabilities | serve`).

Tests: `tests/unit/test_ai_bridge.py` (40), `tests/integration/test_ai_bridge.py` (13, on the Nulavio build and on distribution Firefox), `tests/integration/test_ai_agents_real.py` (opt-in, real Claude Code and Codex CLI). Results: [compatibility matrix](../ai/compatibility.md).
