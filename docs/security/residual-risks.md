# Residual risks and known limitations

Plain-language list of what Nulavio does **not** protect against today. It is linked from the start page and shown in plain language in the README.

## Out of scope by nature

1. **Malware already running as your user.** An infostealer that runs with your account can read your Nulavio profile (cookies, sessions, history), read engine-saved passwords if no Primary Password is set (or capture it when typed), add extensions, change settings and read memory of your processes on many systems. Profile permissions (0700/0600) protect against *other* accounts, not against your own. *Nulavio Guard* only detects cheap, accidental or legacy weakening; malware can bypass it.
2. **Malware with root access.** Everything is exposed.
3. **Physical access to an unlocked session.**

## Specific to the Track A preview

| # | Limitation | Consequence | Plan |
|---|---|---|---|
| R1 | Track A: the engine is Mozilla Firefox as packaged by your distribution | Security fixes arrive when the distribution ships them (`dnf upgrade`). The window title and About dialog say "Mozilla Firefox" | Track B builds are branded (dev build exists); releases need the update SLA, signing and a Safe Browsing key |
| R2 | On **Fedora's** Firefox package (`extensions.autoDisableScopes=0`), any signed XPI dropped into `<profile>/extensions/` is enabled at next start. Mozilla's builds and Track B ask the user first | On Fedora, a same-user process can silently add an AMO-signed extension | Planned: extension-set change alert. Track B keeps Mozilla's default (prompt) |
| R3 | The launcher runs from a git checkout writable by your user | A same-user process could modify the launcher | Packaging into root-owned `/usr` (Phase 6) |
| R4 | Preview chrome theme uses `userChrome.css` and engine CSS variables that change between releases | Cosmetic breakage after engine updates. No security impact (CSS cannot run code; security indicators are not touched) | `nulavio theme off`; built-in theme in Track B |
| R5 | No built-in Nulavio new tab yet (needs a signed or built-in add-on) | New tabs are blank; the start page opens on launch and Home | Track B built-in add-on |
| R6 | uBlock Origin is a third-party extension (GPL-3.0) | False positives and negatives exist; lists update over the network | Per-site toggle; flow C |
| R7 | ETP Strict can break some embeds or logins | Site breakage | Per-site toggle via the shield icon; Mozilla's compatibility exceptions stay on |
| R8 | Password-manager login/autofill not yet certified with real accounts | Only install, signature, background and popup are proven | Manual certification (Phase 4) |
| R9 | KeePassXC pairing proven only in a Fedora container, not yet on a real desktop session or Ubuntu | Desktop-specific issues (Flatpak KeePassXC, portals) may remain | Test on the maintainer's desktop and Ubuntu KDE |
| R10 | Native messaging hosts are shared with your regular Firefox (`~/.mozilla/native-messaging-hosts`) | The same host binaries serve both browsers (still limited to allowed extension IDs) | By design: the engine always reads this path, also in Track B builds (verified in source); `doctor` checks host binaries |
| R11 | Secret Service / KWallet do not isolate applications from each other | Any same-user process can query an unlocked collection | Not used to store web logins; documented |
| R12 | No signed releases, no update channel for the launcher | Users update with `git pull` | Phase 6 |
| R13 | Ubuntu's default Firefox is a Snap and cannot read hidden directories | The preview refuses it; you need the Mozilla APT package | Verify on Ubuntu KDE |
| R14 | Integration tests use Marionette with `--remote-allow-system-access` on throwaway profiles | None for users: the launcher refuses profiles containing automation prefs | Kept test-only |
| R15 | Track B uses its own Google Safe Browsing key, which gets page lists but **not download protection** (malicious-binary list and remote download check are partner-only) | Executable downloads are not checked against Google's download reputation. Page-level phishing/malware protection is active (`test_14`). Track A (distribution Firefox) keeps full download protection | Flow E warning **implemented** (Nulavio Shell): installers and scripts get a warning page with Show in folder / Delete and no Open; downloads are saved without execute permission and never auto-opened (`test_shell`). Still to do: request access to Google's download-protection API. Remote check stays off meanwhile so download details are not sent for nothing ([build](../architecture/build.md#google-safe-browsing-key)) |
| R16 | Track B's Safe Browsing key is under Google's **non-commercial** terms and a default quota | A commercial Nulavio would need another arrangement; a large user base needs a quota review | Recorded as release gate items |
| R17 | Track A (distribution Firefox) has no per-provider consent for suggestions: the engine has one switch for all engines | If the user turns suggestions on in Settings, typing with an alias (e.g. `@google`) also sends keystrokes to that engine | Remote suggestions and trending ship off; Track B adds per-provider consent (patch 0004, `test_search` 05) |
| R18 | Engine profile behaviours Nulavio keeps: creating the first extra profile renames the current one to "Original profile" and turns on the profile chooser at start-up | Surprise on first use | Rename in Nulavio settings; the chooser has its own "don't ask" option. Changing upstream behaviour would need a patch |
| R19 | Profiles started with `--profile <dir>` (Track A launcher, test harness) are not in profiles.ini, so the engine's profile switching is off for them | No selector in Track A | The selector explains this; Track A keeps launcher profiles (`nulavio --profile`) |
| R20 | The "nothing sent while typing" test measures the HTTP(S) requests the browser starts, not DNS | A typed word that looks like a host could still be resolved | Speculative connections and single-word DNS lookups are off (baseline, upstream default `dnsResolveSingleWordsAfterSearch=0`) |
| R21 | An explicit `-P <profile>` on the command line is consumed by the engine before Nulavio sees the link | A link given with `-P` still follows the routing rules | Turn routing off, or use a "Never switch" rule; explicit choices inside the browser carry the routed flag (ADR 0003) |
| R22 | A link that starts the browser (no instance running) is held until the group's rules are loaded | When it stays in that profile it opens in a new tab next to the start page | Kept on purpose: the alternative is reading the group database synchronously at start-up |
| R23 | Any same-user process can send command lines to a running instance (engine remote service over the session D-Bus) | It can open URLs, as any app can | Same-user processes are out of the browser's reach (TB6, S11); routing only moves plain web links and never moves sessions |
| R24 | Links clicked inside pages are routed only when the user turns it on (M5), and only plain clicks | By default, and for forms, redirects, frames, pop-ups, middle-click and Ctrl+click, a link to a ruled site opens in the current profile unless the user picks "Open link in profile" | Opt-in after a [security review](routing-m5-review.md); everything left out is listed there with the reason |
| R25 | ~~The system native-messaging directory is fixed when the engine is built~~ **Resolved 2026-10-26** (patch 0006) | — | The engine reads the system Mozilla directory the distribution has; `check_rpm.sh` and `check_deb.sh` verify `/usr/lib64/mozilla` on Fedora and `/usr/lib/mozilla` on Ubuntu with the same build |
| R26 | An AI agent acts within the permissions it was given | A misled or compromised agent can do anything its grants allow, without asking when the grant says so ([accepted risk](threat-model-ai.md#deliberately-accepted-risk)) | Least-privilege presets, site lists, durations, revoke and emergency stop apply to the next call; the audit shows what happened |
| R27 | A CLI agent runs as the user | Outside Nulavio's tools it can read the agent token and policy file, edit them or start its own browser | The bridge governs only calls made through it; agent sandboxes are the user's option (TB6, [threat model](threat-model-ai.md)) |
| R28 | The AI Workspace's automation endpoint (WebDriver BiDi) listens on 127.0.0.1 while the workspace runs | Any same-user process can connect to it and drive that workspace | Random port, loopback only, the engine rejects web pages (Origin/Host checks); one workspace per agent holds only what that agent opened |
| R29 | Address checks happen before navigation; pages can still make requests and redirects after loading | A page can reach local addresses on its own; DNS answers can change after the check | Engine protections (HTTPS-Only, ETP, Safe Browsing) apply; local network access for pages is a planned engine-level control |
| R30 | An unlocked encrypted profile is readable by any process of your user | Encryption protects locked profiles and copies, not an open session | Lock when not in use; `nulavio run` locks when the browser closes ([threat model](threat-model-unlock.md) U-T3) |
| R31 | Encrypting an existing profile cannot erase old plaintext from SSDs, snapshots or backups | Fragments of the old profile may be recoverable | Create sensitive profiles encrypted from the start; the command warns |
| R32 | If the launcher (or the browser's lock watcher) is killed, the profile stays unlocked after its window closes | Until `nulavio vault lock` or "Lock now" in Settings | `nulavio vault status` and Settings show it; the watcher normally locks within a minute of the window closing |
| R33 | Any process of your user can answer an agent's permission request or edit the AI registry | A CLI agent with shell access could approve itself outside the browser | Requests appear in your window; the activity shows what was allowed; agent sandboxes are your option ([threat model](threat-model-ai.md) AI-T28) |
| R34 | Workspaces of agents that may use files let page processes read their uploads folder | A compromised page process in that workspace could read files placed there for upload | Only that folder; only for agents with `files` not blocked; put only files meant for the agent there |
| R35 | A profile you give an agent exposes its signed-in sessions to that agent | Within its grants, the agent acts as you on those sites | Give profiles only to agents you trust; keep sensitive profiles locked or not given; revoke or stop at any time |
| R36 | If the bridge is killed while it drives one of your profiles, two marked lines stay in that profile's user.js | Remote-agent test preferences stay off (harmless); the "driven by an agent" mark is ignored once the bridge's process is gone | The engine ends with the bridge (parent-death signal through `setpriv`), so no automation endpoint stays open; the lines are removed at the next agent session in that profile; `nulavio-ai-temporary` marks them |
| R37 | A temporary profile deletes only its own folder | Files you save to Downloads, data kept by other apps (a password manager reached through native messaging, the clipboard) and memory pages written to a swap area on disk outlive it; if Nulavio's watcher is killed, the folder stays until the next temporary profile is opened, `nulavio temporary clean`, logout or reboot | The UI says where it is kept and never says "memory only" while a swap area on disk is active; the folder is private (0700) and, on systemd desktops, in memory |
| R38 | Guard at run time is detection, kept in the profile | A program running as you while the profile is unlocked can also rewrite Guard's record, so Nulavio-aware malware can hide its changes; changes are reported at the next start; the installed browser's own files are not checked | The record is encrypted with a protected profile; generic tools and malware are caught ([bypass analysis](hardening.md#guard-at-run-time-what-it-catches-and-how-it-can-be-bypassed)); root-owned packages (S18) protect the installation |
| R39 | uBlock Origin's per-site switch and trusted-sites list are its own | Settings → Site exceptions lists the engine's exceptions, not uBlock Origin's; Nulavio cannot tell whether it filters a given site | Nulavio opens uBlock Origin's own trusted-sites page and never reads or edits its data (no undocumented interfaces) |
| R40 | Encrypted DNS moves who sees your lookups; it does not hide the sites you visit | The chosen resolver sees every name looked up from the profile; the network still sees the server addresses and, where a site does not use Encrypted Client Hello, its name in the TLS handshake; "encrypted only" leaves sites unreachable while the resolver is (including sign-in pages of public networks) | The choice is explicit and explained; Nulavio offers no resolver of its own and keeps the computer's resolver as an equal option |
| R41 | The look-alike login warning compares only with logins the browser's own manager keeps | With Proton Pass, KeePassXC or Bitwarden the vault is never read, so a look-alike of a site saved only there is not caught; a name outside the rules (new confusables, larger edits) is not caught; a third-party manager may still offer to fill on the page after "Continue" | Safe Browsing stays on; the managers do their own origin matching; the comparison runs locally and never sends the address |
| R42 | Raw automation is outside Nulavio's per-call policy | An agent with "Privileged debugging" can do anything WebDriver BiDi allows in its AI Workspace, without asking or an activity record | Blocked unless the user allows it (Full control or an explicit grant); never for the user's profiles; stop, pause and revoke still end the workspace |
| R43 | The built-in assistant's provider sees what is sent to it | Questions and, when included, the page's text reach the provider the user chose; a misled model can act within the assistant's grants | Per-profile permission, explicit "include this page", the recipient named in the panel; tasks under the assistant's agent policy (Restricted by default) |
| R44 | Any program of the user can call the KRunner plugin's service (when installed) | It can make Nulavio open a web address or a search, as any app can open links (R23) | Only http(s) addresses and searches; Smart Profile Routing applies; removing the plugin from Settings deletes its files |
| R45 | With in-page routing on, a page chooses the address another profile opens | A page the user clicks in can put its own identifier in a link to a routed site (linking the two profiles' identities there), make the other profile request a `GET` address on that site with its cookies, and tell from staying alive that the click was routed (one bit per click); a compromised content process can forge the click and frame facts | Opt-in, off by default; a click is required; `GET` only, top-level only, one per click; only to sites the user's own rules send there; nothing but the address moves ([review](routing-m5-review.md)) |
| R46 | The confined mode is opt-in and partial, and Ubuntu is untested | Without `--confined` the browser can read the whole home folder; with it, the session bus is not filtered, Downloads is writable, and native hosts that need home files fail. On Ubuntu, the `.deb`'s AppArmor profile and bubblewrap's own namespaces are checked only in containers on Fedora's kernel | [Spikes](phase5-spikes.md#bubblewrap): what it blocks and what it does not; check `about:support` (user namespaces) on a real Ubuntu 26.04 host before release |
| R47 | The sensitive-sites profile relies on a file and a normal close | Deleting its `user.js` turns its settings off (Settings then stops marking it); after a crash its data stays until the next normal close; a program running as the user can read it while it is open | Settings shows it only while the file says so; [spikes](phase5-spikes.md#sensitive-sites) |
| R48 | Phone unlock is not yet verified on a real phone | The Companion is tested against the desktop's code (Java on the JVM, the browser pages, the reference phone); Keystore, StrongBox, BiometricPrompt, NSD and the camera are untested on hardware | Phone unlock stays off the alpha's feature list until the Galaxy S24+ run passes ([ADR 0005](../adr/0005-phone-profile-unlock.md#implementation-s11-2026-10-27)) |
| R49 | The local network sees that a Nulavio phone operation is happening | The phone announces `nv1-p-…`/`nv1-u-…` over mDNS for up to 5 minutes (pairing) or 60 seconds (unlock); names derive from one-time ids and reveal no profile or desktop | Short windows; names are not linkable across operations |
| R50 | Windows and iOS are not supported | Nothing ships for them; the Companion is Android only | Stated in the [evaluation](../research/windows-ios-evaluation.md); the product and the site claim Linux (and Android for the Companion) only |
| R51 | Engine security updates depend on the maintainer's machine and on GitHub's schedule | With the local timer off (it is opt-in) and Actions late, skipped or out of minutes, a Firefox security release can be noticed up to about 14 hours late (the longer gap between the two daily runs), and with no bound while Actions is skipped or out of minutes; signing and publishing always wait for the maintainer | Two detectors (local timer every 30 minutes, Actions twice a day), an issue that @mentions the maintainer, and the 72-hour deadline with a failing job ([update policy](../architecture/update-policy.md)) |
| R52 | Urgency is read from the text of Mozilla's advisories | Their YAML is not a stable interface, and the "exploited in the wild" wording rules can misjudge a sentence | A missing, unreadable or unclear advisory counts as urgent, and so does a year's list of advisories that is missing, empty or not a list (except the current year while no newer release came out in it); every release keeps the 72-hour deadline; platform notes never lower urgency |
| R53 | The Companion's build tooling (Android Gradle plugin 9.4.1) uses libraries with known advisories, and new Gradle artifacts are trusted on first download | Ten advisories in build-time libraries (Bouncy Castle 1.80.2, Guava, jdom2, jose4j, HttpClient, Commons Lang, Kotlin Gradle plugin) are accepted until 2026-12-31; none is in the APK. A regenerated verification file records what the repositories serve that day, checked only against their own published checksums | The daily watch fails on any new or expired finding; each new hash is reviewed with `review_gradle_verification.py`; planned: PGP signature verification per publisher ([dependency updates](dependency-updates.md)) |
| R54 | Code scanning reports problems after the push | Commits go straight to `main`, and a private repository on the free plan has no branch protection, push protection or code scanning: the CI job `security` (gitleaks, Opengrep with Nulavio's rules, ShellCheck, zizmor, actionlint) finds a leaked secret or a forbidden pattern only once it is on GitHub, and there is no interprocedural taint analysis (no CodeQL) | Optional pre-commit hook for secrets (`git config core.hooksPath scripts/git-hooks`) and `scripts/security/scan.sh` before pushing; make `security` a required check and turn on push protection if the repository gets branch protection or becomes public ([code scanning](code-scanning.md)) |
