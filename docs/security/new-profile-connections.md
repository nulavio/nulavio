# What a new profile contacts by itself

Every address a new Nulavio profile asks for before the person does anything: who asks, what the request carries and why it is there. Pages, searches and extensions the person adds are not covered: this is the browser left alone.

The list comes from a record, not from reading settings. A package of the 160.0 build was started as its desktop entry starts it (no flags, a new home directory, Portuguese) and left alone for ten minutes with the engine's own network log on; a second run through the test harness recorded the headers and who asked. Nothing new appeared after the first 61 seconds. [`new-profile-connections.json`](new-profile-connections.json) holds the same hosts for the tests: an integration test starts a new profile, waits for that start-up work and fails on an address that is not listed.

## What every request shows

Each of them shows the server the computer's network address, Firefox's own User-Agent (`Mozilla/5.0 (X11; Linux x86_64; rv:160.0) Gecko/20100101 Firefox/160.0`, not Nulavio's name), the browser's languages (`Accept-Language`) and `Sec-GPC: 1`. None of the requests the harness run observed carried a cookie or a body. The rows below say what a request carries beyond that.

## Not on the list

The record shows no request for any of these, and the integration test fails if one appears:

- Telemetry, studies and experiments (`incoming.telemetry.mozilla.org`, Normandy, Nimbus): off in both tracks.
- Mozilla's location service: no region lookup (`browser.region.network.url` is empty).
- Google's update service (`update.googleapis.com`): not asked about a DRM module that is off; pinned by `test_mozilla_features` 03c.
- An engine update server: the build is made without the engine's updater (`--disable-updater` in `browser/build/mozconfig`); updates come as packages.
- An encrypted-DNS resolver: none is used until the person chooses one in the first run or in Settings.
- Search suggestions, sponsored tiles and new-tab feeds.

## How the list is kept

- `tests/integration/test_new_profile_connections.py` starts a new profile with the engine's network log on (`MOZ_LOG=nsHttp:1,nsHostResolver:4`, written from the first moment of the process), leaves it alone for 75 s and compares every address asked for, and every name resolved, with the JSON file. A host that is not there, or a listed host asked over plain http when its entry does not say so, fails the test with the address. It needs the network: offline the engine does not even ask Remote Settings, and the test says that this is what it is missing, apart from an unlisted address.
- `tests/unit/test_new_profile_connections.py` keeps this page and the JSON file naming the same hosts, and refuses a few hosts outright (telemetry, the location service, Google's update service): adding one of those is a decision, not a list update.
- `scripts/research/new_profile_connections.py <build>/nulavio/nulavio` makes the longer record this page was written from (ten minutes, a plain start with no remote control) and marks every host that is not listed.
- When the test fails after an engine or uBlock Origin update: record again, read what the new request carries, add the row here and the host to the JSON file in the same change. If it should not be there, switch it off in both tracks instead ([hardening](hardening.md)).

## Decisions this list raises

Each has a recommendation; none is carried out by this page.

1. **OpenH264 is downloaded without asking.** Recommendation: keep. A video call with a peer that only offers H.264 can fail without it; it comes from Cisco because Cisco's licence covers only the binary Cisco distributes, so it cannot be shipped inside the package; the download is checked against the hash in Mozilla's list. The other choice is to keep the plugin off until the person asks, and lose H.264 in calls by default.
2. **The network check is plain http.** Recommendation: keep. It sends nothing but the request itself, and without it the sign-in page of a hotel or airport network is not offered. The other choice (`network.captive-portal-service.enabled` off) removes one unencrypted request per start.
3. **The plugin and built-in add-on checks tell Mozilla the kernel, GTK and libpulse versions, and that the browser is Nulavio.** Recommendation: send a generic system name and no distribution id in those two addresses. On 2026-11-12 Mozilla's answers were byte for byte the same with `Linux/default/default` in place of those details, for both checks. The cost: if Mozilla ever makes a plugin rule depend on the system version, Nulavio gets the generic answer.
4. **Mozilla's channel for updating built-in add-ons is on.** Recommendation: keep. It is how Mozilla ships an urgent fix between engine releases, the code is signed by Mozilla like the engine's own, and the answer today is empty. The other choice is to turn it off and rely on Nulavio's own release schedule for such fixes.
5. **The add-on details request names the installed add-ons to Mozilla once a day.** Recommendation: keep. For an add-on the person installed, the update check names it to the same party anyway. What this request adds, as far as the engine's source shows, is the engine's built-in themes (the update check leaves out what cannot be updated), which are the same in every copy, and the browser's language. Turning it off loses names, descriptions and icons in the add-ons page.

## Limits of the record

- One machine, one network, one day, Portuguese. A system with a proxy, another language or a sign-in network asks for other things; the test reports them.
- Ten minutes. Work the engine does once a day (the checks above) was seen once; work it does less often than that was not seen at all.
- The record names hosts and addresses. The harness run started observing 2 s after the process: for the requests before that (the content blocker's install, the first network check, the push connection) only the address is recorded; what a WebSocket carries after its greeting was read in the engine's source, not on the wire.
- The harness sets the first run as done; the plain start showed the first run and asked for the same hosts.
