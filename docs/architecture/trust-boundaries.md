# Trust boundaries

Zero Trust here means: every boundary states **who is on each side, how identity is established, what may cross, and what enforces it**. Nothing is trusted just because it runs locally.

| ID | Boundary | Untrusted side | Identity / authentication | What may cross | Enforced by | Verified |
|---|---|---|---|---|---|---|
| TB1 | Web content ↔ content process | Any website | Origin (scheme+host+port); TLS certificate | HTML/JS/CSS/media | Gecko site isolation (Fission), same-origin policy, CSP | `test_04`, `test_06` |
| TB2 | Content process ↔ parent | Possibly compromised renderer | Process identity of the IPC channel | IPC messages validated by the parent | seccomp-bpf, user namespace, IPC validation (upstream) | `test_04` (presence) |
| TB3 | Extension ↔ browser and pages | Any extension, incl. pinned ones | Mozilla signature (AMO); extension ID | WebExtension API calls within granted permissions | Engine permission model, private-browsing opt-in, blocklist | lock tests, `test_08` |
| TB4 | Browser ↔ native messaging host | Host binary outside the sandbox | Manifest name + `allowed_extensions` ID list; the app's own pairing (e.g. KeePassXC association keys) | JSON messages over stdio | Engine (manifest lookup), host app | `doctor` (manifest sanity) |
| TB5 | Browser/launcher ↔ filesystem | Other local accounts | Unix UID | Profile files | 0700/0600 modes, symlink refusal, umask 077 | `test_09`, path tests |
| TB6 | User session ↔ other same-UID processes | Any process of the same user | **None** (same UID) | Everything | Nothing in the browser. Host hygiene only | Documented: [residual risks](../security/residual-risks.md) |
| TB7 | Network ↔ browser | Network | TLS (WebPKI, CRLite/OCSP), HTTPS-Only | HTTP(S) | Engine TLS stack; HTTPS-Only | `test_06` |
| TB8 | Update and supply channels ↔ installation | Mirrors, CDNs, registries | RPM GPG signatures (distribution), AMO signatures, Mozilla release key (pinned), SHA-256 pins; Nulavio's own dnf and APT repositories signed with its release key, whose repository files come from the site, not the bucket | Packages, XPIs, source tarballs | dnf, apt, engine, `extensions.py`, `verify_firefox_release.py` | integrity unit tests, `test_signed_repo.sh`, `test_kms_signing.sh`, `test_apt_repo.sh` |
| TB9 | Launcher ↔ engine | Environment variables and URL arguments from a desktop entry or link | n/a | A validated URL, fixed flags | `build_command()` allow-list, `launch_env()` stripping | engine unit tests |

From the settings groups: direct calls to the same module functions | API schemas; validation in the modules whoever calls (`NulavioSearch`, `NulavioProfiles`, `NulavioPrivacy`, `NulavioRouting`: https-only addresses, alias and name patterns, colour and icon allow-lists, a locked setting refused); nothing is read from the settings page's address; the engine's Search Service and profile service | `test_search` 08, `test_profiles` 03, `test_shell.PrivilegedApiTest`, `test_settings_native`, `test_settings_dns`, `test_settings_profiles`, `test_settings_routing` |
| TB12 | Address bar ↔ search providers | Search providers | TLS; engine id | Search terms when the user searches. Typed text **while typing** only to engines listed in `nulavio.search.suggest.optin` | Seed prefs (suggestions, trending off) and patch 0004 at the single remote-suggestion fetch point | `test_search` 02, 03, 05 |
| TB13 | One profile's instance ↔ another's (same UID) | Another instance, any same-user process (see TB6) | Profile directory and its engine lock | Activation and routed command lines only (`--profiles-activate`, `--nulavio-routed -new-tab <url>`), over the engine's remote service (session D-Bus) or as an argument list; never cookies, sessions or storage | Engine remote service, profile lock (`launchInstance`, `deleteProfile`); the routed flag stops re-routing | `test_profiles` 05, `test_routing` 04–06 |
| TB14 | Other applications ↔ Nulavio (links); the address bar (typed addresses) | Any app that opens a URL (email, chat, documents), any same-user process | None (same user, session D-Bus) | Command lines with URLs | Nulavio's command-line handler runs before the browser's, and patch 0005 asks routing before an address-bar load: only plain URL forms and `http(s)` are routed, decided before any request; POST, downloads, private windows and anything else are left to the browser | `test_routing` |
| TB15 | AI agent ↔ AI Bridge ↔ AI Workspace ([ADR 0007](../adr/0007-ai-bridge.md)) | The agent and the model (any page it read may have steered it); same-user processes | Token per agent in its MCP config (SHA-256 stored); identifies the configuration, not the program | Tool calls with validated arguments; results with page data marked untrusted | Policy Decision Point on every call (stop, revocation, site list, grants, presets); addresses classified before navigation; one engine profile per agent; BiDi on loopback with a random port | `test_ai_bridge` (unit, engine), `test_ai_agents_real` |

| TB17 | Website visitor ↔ the waitlist of nulavio.net (`site/_worker.js` on Cloudflare Pages ↔ a D1 database). An entry changes only through its link: a second sign-up changes nothing and gets a key that opens nothing, and an entry from before links existed gets none. `_routes.json` limits the worker to `/api/*` and the two link pages; the pages' CSP has `form-action 'self'`; the link page is `no-store`, `noindex` and sends no referrer. **Not enforced here:** rate limits (a WAF rule on the zone, maintainer). **Limits:** whoever signs an address up first holds the only link to it, and its owner, signing up later, is not told (R69). The key is in an address, so it is in the browser's history and in the host's request logs; whoever has it can remove that one entry and learns nothing else. Someone whose address was signed up by another person, who lost the link or who signed up before links has to write to the project, which removes the entry by hand after an answer from that address. Response times were compared on the local runtime only, not on Cloudflare. | TB19 | Release build on Blacksmith ↔ the signing job | Blacksmith (the machine and its operator) and everything the build downloads | The packages are signed only after a GitHub-hosted job in the `release` environment checks their build-provenance attestation (this workflow, `refs/heads/main`) and the `release` environment's approval is given (by the maintainer's account, see TB18) | Packages, SBOMs and `manifest.json` (one workflow artifact); the build holds the Google Safe Browsing key, never the signing role or the R2 token | `release.yml`: the build and publish jobs on different machines, environments `build` and `release`; `release_manifest.py verify` (committed tree on `main`, SHA-256 of every file); the attestation names where a package was built, not that the machine was honest | `test_release_workflow.py` |

## Rules derived from the boundaries

1. Anything crossing TB3 or TB4 is treated as untrusted by Nulavio code. Nulavio never reads vault contents or intercepts provider messages, and does not read extensions' storage, with one exception: which filter lists are selected in uBlock Origin, the content blocker Nulavio itself installs. It is read, never written, to say in Settings whether cookie notices are hidden ([ADR 0011](../adr/0011-nulavio-ui-native-not-an-extension.md), step 7; [R39](../security/residual-risks.md)).
2. A boundary without enforcement (TB6) is documented as residual risk, never presented as protected.
3. Configuration that could weaken TB1, TB2 or TB7 is detected by Guard and blocks the launch at critical severity.
4. New integrations must add a row here before they merge.
